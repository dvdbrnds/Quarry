1 Sentry: Stop swallowing errors

Catches the "silently broken" bugs that caused 27 rework commits

Four of your worst clusters started with errors being silently swallowed — Stripe webhooks dropping payments, audit trail failing invisibly, capacity audit timing out without a trace, backups 500-ing with no notification. Sentry catches every unhandled exception the moment it happens and pings you. You don't need a staging environment to find these bugs — you need production to tell you about them instead of hiding them.

FastAPI integration

File: hounddog/main.py
Add this before your app starts — above the FastAPI() constructor. 
import sentry_sdk

sentry_sdk.init(
    dsn=os.environ.get("SENTRY_DSN"),
    traces_sample_rate=0.1,          # 10% of requests get performance traces
    profiles_sample_rate=0.1,
    environment=os.environ.get("DEPLOY_ENV", "production"),
    release=os.environ.get("GIT_SHA", "dev"),
    # Tag every error with the commit that introduced it
    before_send=lambda event, hint: {**event, "tags": {
        **event.get("tags", {}),
        "deploy_sha": os.environ.get("GIT_SHA", "unknown"),
    }},
)

Catch the silent killers explicitly

Everywhere you currently have except Exception: pass or except Exception as e: logger.error(e), add Sentry capture so it actually reaches you:

try:
    result = await call_sis_api(moravian_id)
except Exception as e:

2 Axiom: See everything that happens

Structured request logging that replaces "add diagnostic endpoint" commits

Sentry catches errors. Axiom shows you everything — every request, every response time, every slow query, every external call. This replaces the pattern where you added a diagnostic endpoint to figure out what was going on (you did this at least 4 times across Stripe, audit trail, tickets, and capacity).

Structured request logging middleware

File: hounddog/middleware/axiom_logging.py
One middleware that logs every request with all the context you'd want when debugging. 
import time, os, httpx
from starlette.middleware.base import BaseHTTPMiddleware

AXIOM_TOKEN = os.environ.get("AXIOM_TOKEN")
AXIOM_DATASET = os.environ.get("AXIOM_DATASET", "hounddog")
AXIOM_URL = f"https://api.axiom.co/v1/datasets/{AXIOM_DATASET}/ingest"

class AxiomRequestLogger(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        start = time.monotonic()
        response = None
        error = None

        try:
            response = await call_next(request)
            return response
        except Exception as e:
            error = str(e)
            raise
        finally:
            duration_ms = (time.monotonic() - start) * 1000
            user = getattr(request.state, "user", None)

            event = {
                "_time": time.time(),
                "method": request.method,
                "path": request.url.path,
                "status": response.status_code if response else 500,
                "duration_ms": round(duration_ms, 1),
                "user": user.email if user else None,
                "error": error,
                "deploy_sha": os.environ.get("GIT_SHA", "unknown"),
            }

            # Fire and forget — never block the response
            try:
                async with httpx.AsyncClient() as client:
                    await client.post(AXIOM_URL,
                        json=[event],
                        headers={"Authorization": f"Bearer {AXIOM_TOKEN}"},
                        timeout=2.0)
            except:
                pass  # Logging must never break the app

What to query when debugging

Instead of adding diagnostic endpoints, you open Axiom and query:

// "Why are Stripe webhooks failing?"
method == "POST" and path == "/api/stripe/webhook" and status >= 400

// "What's slow right now?"
duration_ms > 2000 | sort -duration_ms

// "Did my last deploy break anything?"
deploy_sha == "abc123" and status >= 500

// "What did this user see?"
user == "student@moravian.edu" | sort _time
What this prevents
The "add diagnostic endpoint" cycle (4+ instances). The "what is even happening in production" blind spots. The capacity audit timeout that took 7 commits — you would have seen duration_ms: 32000 on the SIS call in Axiom and known immediately.

3 Infrastructure Guardrails

A constraints file + API wrapper that make WAF-blocked patterns impossible

This is not a staging environment. This is a file in your repo that encodes everything you've learned about Moravian's infrastructure the hard way, plus a thin wrapper that enforces it in code so you can never hit the same wall again.

The constraints file

File: INFRASTRUCTURE.md (repo root)
Every time you discover a new constraint, add it here. Claude reads this before writing code. 
# Moravian Infrastructure Constraints
# Last updated: 2026-09-18

## WAF (Web Application Firewall)
- HTTP DELETE is BLOCKED. Use POST /revoke or PATCH with status change.
- HTTP PATCH field names containing "delete" are BLOCKED. Rename fields.
- Request bodies over ~10MB may be silently truncated.

## CSP (Content Security Policy)
- Google Maps requires: *.googleapis.com, *.gstatic.com in script-src
  and connect-src, plus fonts.googleapis.com in style-src.
- Okta requires: login.moravian.edu AND *.okta.com in frame-src
  and connect-src.

## Container (Coolify / Docker)
- Filesystem is EPHEMERAL. Never persist to disk. Use PostgreSQL.
- No cron. Use APScheduler or background tasks in the web process.
- Backups must write to external storage (S3/volume), not /tmp.

## Okta SSO
- ID token may not contain groups claim. Always fall back to /userinfo.
- Callback page must initialize auth SDK independently.

## Database
- Startup migrations race with web workers. Use Alembic or single-worker
  migration entrypoint.
- ARRAY columns: use sqlalchemy.dialects.postgresql.ARRAY, not generic.

API route protection

A decorator that refuses to register DELETE or PATCH routes, forcing you to use safe alternatives at definition time instead of discovering the failure in production:

# hounddog/utils/waf.py

from fastapi import APIRouter
import warnings

class SafeRouter(APIRouter):
    """APIRouter that warns on WAF-blocked HTTP methods."""

    def api_route(self, path, *, methods=None, **kwargs):
        if methods:
            blocked = {"DELETE", "PATCH"} & {m.upper() for m in methods}
            if blocked:
                raise ValueError(
                    f"WAF blocks {blocked} — see INFRASTRUCTURE.md. "
                    f"Use POST with an action verb instead: "
                    f"POST {path}/revoke, POST {path}/archive"
                )
        return super().api_route(path, methods=methods, **kwargs)

    def delete(self, *a, **kw):
        raise ValueError("WAF blocks DELETE — use POST with /revoke or /archive")

    def patch(self, *a, **kw):
        raise ValueError("WAF blocks PATCH — use PUT or POST")

Then swap APIRouter for SafeRouter in your route files. If you or Claude try to add a DELETE endpoint, it blows up immediately with a clear message instead of silently failing in production three weeks later.

What this prevents
The WAF rediscovery cycle (10 commits, 5–6 hours, happened three separate times). The branding-stored-to-disk bug (5 commits). The Okta groups-missing-from-ID-token bug (discovered twice). Every infrastructure constraint you encode here is one you never hit again.

4 Targeted Tests: 200 Lines That Prevent 30 Commits

Not a test suite. Not CI. One file you run before pushing when you touch these areas.

What this is NOT
This is not pytest with fixtures and mocks and 80% coverage targets. That would slow you down and you'd stop using it. This is one Python file with direct assertions on the pure functions that keep breaking. You run it when you touch access logic or matching code. That's it.
File: hounddog/tests/smoke.py
Run with: python tests/smoke.py — no pytest needed, no dependencies. 
"""
Smoke tests for the logic that keeps breaking.
Run: python tests/smoke.py
No frameworks. No fixtures. Just assertions.
"""
from datetime import datetime, time

# === After-hours access (8 rework commits) ===

def test_after_hours_access():
    from hounddog.services.access import check_lot_access

    # Commuter at 3:59 PM — should NOT have FSC access
    assert not check_lot_access("commuter", "FSC", time(15, 59))

    # Commuter at 4:00 PM — SHOULD have FSC access
    assert check_lot_access("commuter", "FSC", time(16, 0))

    # Commuter at midnight — edge case
    assert check_lot_access("commuter", "FSC", time(0, 0))

    # Faculty at any time — always has access
    assert check_lot_access("faculty", "FSC", time(8, 0))
    assert check_lot_access("faculty", "FSC", time(23, 59))

    print("  ✓ after-hours access")


# === Lot normalization (4 rework commits) ===

def test_lot_normalization():
    from hounddog.services.lots import normalize_lot_code

    # These all mean the same lot
    assert normalize_lot_code("Lot M") == "M"
    assert normalize_lot_code("lot m") == "M"
    assert normalize_lot_code("M") == "M"
    assert normalize_lot_code("  lot M  ") == "M"

    # Comma-joined lots should split
    assert normalize_lot_codes("M, FSC, G") == ["M", "FSC", "G"]

    print("  ✓ lot normalization")


# === Capacity calculation (4 rework commits) ===

def test_capacity_matching():
    from hounddog.services.capacity import match_lot_to_capacity

    lots = [{"id": 1, "name": "Lot M"}, {"id": 2, "name": "FSC"}]

    # Match by name
    assert match_lot_to_capacity("Lot M", lots) == 1
    # Match by name without prefix
    assert match_lot_to_capacity("M", lots) == 1
    # Match by ID
    assert match_lot_to_capacity(2, lots) == 2
    # No match returns None, not crash
    assert match_lot_to_capacity("ZZZZZ", lots) is None

    print("  ✓ capacity matching")


if __name__ == "__main__":
    print("Running smoke tests...")
    test_after_hours_access()
    test_lot_normalization()
    test_capacity_matching()
    print("All passed.")
Important
The imports above assume you extract the access logic, normalization, and capacity matching into standalone pure functions (no database, no request context). That's the refactor: pull these out of your route handlers into service modules that take simple arguments and return simple values. The tests then just call those functions directly.

5 Pre-Push Business Rules Spec

Five minutes of writing that prevents five hours of code churn

The freshmen exclusion saga (6 implementations in one day) and the lottery config UI churn (5 commits) weren't bugs. They were "what do we actually want" problems solved by trial and error in code. The fix is embarrassingly simple: before coding a business rule change, write one paragraph describing the rule in plain English. Keep it in a living doc.

File: BUSINESS_RULES.md (repo root)
This is the source of truth for "what the system is supposed to do." 
# Business Rules — Quarry Parking

## Lottery Eligibility
- Freshmen (class year = current academic year + 4) are excluded from
  residential parking lotteries by default.
- Each lottery can override this with its own "Allow Freshmen" toggle.
- Commuter permits are NOT subject to the freshmen restriction.

## After-Hours Access
- Commuter permits gain access to FS and FSC lots after 4:00 PM.
- "After 4:00 PM" means >= 16:00 local time. Midnight (00:00) counts.
- Faculty/staff permits have 24/7 access to all assigned lots.
- Extended Premium Commuter has full-time access to FS, FSC, and streets.

## Permit Renewals
- Permits expire June 30 annually.
- Renewal emails offer one-click Renew or Decline.
- Decline soft-deletes the permit (recoverable).

When you or Claude are about to change access logic or lottery rules, you check this file first, update it if the rule is changing, then implement the updated rule. One commit instead of six.

Implementation Order

Fastest impact first, each step takes less than an hour

The order matters
Sentry goes first because it's the fastest to set up and immediately catches the entire class of "silent failure" bugs. Axiom goes second because you already have the account — you just need the middleware. The constraints file and tests come third because they require extracting some logic into pure functions. None of these block each other.

Day 1 (30 min): Add Sentry to Hounddog. Create project at sentry.io, add the DSN to Coolify env vars, add the 4-line init to main.py, redeploy. You're immediately protected against silent errors.

Day 1 (30 min): Add Sentry to BirdDog. Add the Swift package, 5-line init in app startup. Next TestFlight build has crash reporting with screenshots.

Day 2 (30 min): Add Axiom middleware. Drop in axiom_logging.py, add the middleware to the app, add the env vars. Every request is now logged with timing, user, and deploy SHA.

Day 2 (20 min): Create INFRASTRUCTURE.md and BUSINESS_RULES.md. You already know all of this — it's just writing it down.

Day 2 (10 min): Add the Claude/Cursor instructions to CLAUDE.md. Paste the block above.

Day 3 (1 hr): Build SafeRouter and swap it into your route files. Extract access logic into a pure function. Write the first smoke test. This is the only step that touches existing code.

What This Is Not

This playbook deliberately avoids everything that slows down tactical development:

No staging server. You don't need a second Coolify instance. Your production IS your staging — you just need it to tell you when things break (Sentry) and let you see what happened (Axiom).

No CI/CD pipeline. No GitHub Actions, no build gates, no required checks. You push, you redeploy. That doesn't change.

No code review process. You and Claude move fast. The guardrails are in the code (SafeRouter), in the docs (INFRASTRUCTURE.md), and in the tooling (Sentry/Axiom) — not in a process that requires you to stop and wait.

No test coverage mandates. One file, ~200 lines, covering only the things that have actually broken repeatedly. Not a test suite. A targeted weapon against your specific rework patterns.
